# 架构与第一轮边界

产品名 Resume Engineering；技术标识 resume-engineering。面向不同职业背景，默认参考视觉为深色黑白灰蓝模块化网站、浅色黑白两页职业简历。第二轮才提取并验收脱敏视觉模板；本轮没有复制任何参考人物内容。

## 七个阶段与十个模块

阶段顺序：策划 → 事实整理 → 网站 → AI → 简历 → 审核 → 复盘。允许跳过非目标模块，或从已有项目中的任一模块开始；先检查依赖是否满足。

模块：planning、facts、glossary、media、privacy、website、assistant、resume、release、retrospective。

数据方向：原始描述/证据 → 结构化事实 → 针对用途审核的内容 → 各类输出。
网站和公开AI仅消费 public_website/public_ai 获准内容；投递附件消费 targeted_resume 获准内容；公开PDF必须再通过 public_website 审核。

## 两种存储边界

公开工具仓库仅包含规则、空白契约、代码、合法可再分发资源及标明虚构的例子。
使用者工作目录包含真实资料。其 project 状态、依赖图、报告和日志也可能暴露职业信息，默认私人，不能因为它们是“元数据”而公开。

## 实现路线

1. 框架：模块、Schema、权限、状态、依赖、局部变更流程与契约测试。
2. 模板：脱敏网站视觉、HTML/CSS简历视觉、照片模式及演示资料。
3. 实现：导入/合并、增量生成、AI接入、导出与校验工具。避免锁定供应商。
4. 验证：虚构人物端到端试跑、资料冲突、权限收回、工具缺失、断点续做。
5. 发布：资源许可、完整隐私复核、安装文档、全新Git仓库与GitHub发布。

第一轮完成不自动进入第二轮。后续只有实际运行过的能力标记为已验证。

## 兼容与成本

Markdown为说明，JSON为规范数据；Excel导出列为后续能力，不能把词汇库当作技能证据。运行时按可用工具选择；缺图像工具可直接用授权原图，缺云账户可交付本地产物。
Token优化以减少重复读取、保留精简索引、脚本摘要和增量产物为依据。记录实际用量或 null，不推算虚假节省百分比。
